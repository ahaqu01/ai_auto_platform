# AI 工程化与交付平台——第一阶段迭代任务与验收标准

| 属性 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 计划周期 | 8 周（4 个双周 Sprint） |
| 建议团队 | 后端 2、前端 1、Agent 1、DevOps/测试 1；产品/架构共享 |
| 更新日期 | 2026-08-20 |

## 1. 迭代目标

交付一套可部署的第一阶段平台，真实跑通：

```text
注册并验证邮箱
→ 创建企业和项目
→ 邀请工程师
→ 浏览器分片直传 OSS
→ 创建 artifact.copy 任务
→ 本地 Agent 自动领取任务
→ 下载输入、生成结果、上传输出
→ 实时查看日志和状态
→ 下载结果并查询审计记录
```

## 3. 开发准入与完成定义

### 3.1 Definition of Ready

任务进入 Sprint 前必须满足：

- 关联至少一个需求编号和一个验收场景。
- API/事件/表结构变更已评审或明确无需变更。
- 权限、审计、幂等和错误码已定义。
- 外部依赖、测试数据和环境可用。
- 工作量不超过 3 个工程日；超过则继续拆分。

### 3.2 Definition of Done

- 代码合并主干，至少一人评审。
- 单元、集成和契约测试通过；无跳过的关键测试。
- OpenAPI、迁移、配置样例和运维说明同步更新。
- 结构化日志、指标、Trace 和必要告警已加入。
- 权限拒绝和异常路径完成测试。
- 部署到 Staging 并由产品/QA 按验收步骤通过。
- 无 Critical/High 漏洞；其他漏洞有责任人和期限。

## 5. 验收环境

验收必须在 Staging 完成：

- 与生产同构的 HTTPS 域名、RDS/自建 PostgreSQL、Redis、Temporal 和私有 OSS Bucket。
- 两台 API 实例、至少两台 Temporal Worker。
- 两台 Ubuntu Agent：A 最大并发 1，B 最大并发 2。
- Mailpit/测试邮箱、可控制的弱网和断网环境。
- 测试用户分别属于企业 A、企业 B，另有平台管理员。
- 测试文件：1 KB、100 MB、1 GB 和超过 20 GB 的声明文件。

## 6. 功能验收场景

### 6.1 身份

#### AC-AUTH-01 注册与验证

**Given** 未注册邮箱；**When** 用户提交合规密码；**Then** 创建 PENDING 用户并发送验证邮件，验证后状态为 ACTIVE，验证 Token 再次使用返回 409。

#### AC-AUTH-02 邮箱唯一与信息保护

使用相同邮箱不同大小写重复注册不能生成第二用户；忘记密码无论邮箱是否存在均返回相同 202 响应。

#### AC-AUTH-03 登录和轮换

正确登录返回短期访问令牌并设置安全 Refresh Cookie；刷新后旧 Refresh Token 失效，重放旧 Token 会撤销该轮换链。

#### AC-AUTH-04 退出

退出后访问令牌在有效期内可按策略短暂有效，但 Refresh Token 立即不可用；安全敏感企业可配置会话即时吊销列表。

#### AC-AUTH-05 密码重置

重置 Token 30 分钟过期且只能使用一次；成功重置后其他会话全部撤销。

#### AC-AUTH-06 登录限流

同账户/IP 连续失败达到阈值后返回 429；响应不说明账户是否存在；审计记录限流事件但不记录密码。

#### AC-AUTH-07 资料与会话

用户可修改姓名/时区并撤销指定会话，不能查看其他用户会话。

### 6.2 企业和项目

#### AC-ORG-01 创建企业

邮箱未验证用户返回 403；已验证用户创建后成为唯一 OWNER，企业列表立即可见。

#### AC-ORG-02 邀请

管理员邀请邮箱并指定 MEMBER；Token 只可接受一次，7 天后失效；已撤销邀请不可接受。

#### AC-ORG-03 成员管理

管理员可调整 MEMBER/ADMIN；普通成员无权操作；所有尝试均写审计。

#### AC-ORG-04 最后所有者

移除或降级企业最后一个 OWNER 返回 409 `LAST_OWNER_REQUIRED`，数据不改变。

#### AC-PRJ-01 项目创建

同企业项目 code 不可重复，不同企业可以相同；列表只包含当前企业可见项目。

#### AC-PRJ-02 项目成员

只能添加企业成员；移出企业后项目权限立即消失。

#### AC-PRJ-03 项目角色

VIEWER 无法上传或创建任务；ENGINEER 可上传/创建任务但不能管理成员；ADMIN 可管理项目成员。

#### AC-PRJ-04 归档

归档项目允许读取，创建上传或任务返回 409；恢复后可继续创建。

### 6.3 资产

#### AC-AST-01 分片上传

上传 1 GB 文件，分片大小符合服务端配置，完成后 Artifact 状态为 AVAILABLE，大小及 SHA-256 正确。

#### AC-AST-02 断点续传

上传 40% 后断网，恢复后只上传缺失分片，最终内容摘要一致。

#### AC-AST-03 完成校验

客户端伪造分片或大小时完成接口失败，Artifact 不可用且写审计/错误指标。

#### AC-AST-04 不完整资产

UPLOADING、VERIFYING、FAILED、QUARANTINED 资产均不能创建任务输入。

#### AC-AST-05 下载授权

有权限用户获得 10 分钟 URL；过期后不可用；VIEWER 可否下载由项目权限配置决定。

#### AC-AST-06 Key 防注入

客户端提交 `../`、其他企业前缀或自定义 objectKey 均不影响服务端生成 Key。

#### AC-AST-07 删除保护

运行任务引用的资产删除返回 409；无引用资产软删除后列表不可见，OSS 删除由异步清理策略执行。

#### AC-AST-08 Agent 最小权限

当前任务凭证只能读指定输入、写指定暂存前缀；读取其他项目或列举 Bucket 返回拒绝。

### 6.4 Agent

#### AC-AGT-01 一次性注册

有效 Token 完成一次注册；相同 Token 第二次失败；Agent 私钥只存在本地且权限为 0600/等效安全权限。

#### AC-AGT-02 出站连接

本地防火墙没有公网入站规则时，Agent 仍能通过 443 建立 mTLS 通道。

#### AC-AGT-03 在线判定

心跳正常为 ONLINE；停止心跳 60 秒内变 OFFLINE；恢复后无需重新注册回到 ONLINE。

#### AC-AGT-04 禁用与吊销

禁用 Agent 后不再分配新任务；证书吊销后无法调用 Agent API。

#### AC-AGT-05 并发与 Drain

maxConcurrency=1 时同时只执行一个任务；Drain 后现有任务继续，新任务不再分配。

#### AC-AGT-06 本地安全

非 Agent 系统用户无法读取身份目录；任务进程无法挂载身份目录；敏感凭证不出现在日志中。

#### AC-AGT-07 Echo 执行器

执行预定义消息和延时参数，持续回传日志；传入未定义字段或命令参数由 Schema 拒绝。

#### AC-AGT-08 Copy 执行器

下载输入、计算摘要、复制并上传输出；任务结束后清理工作目录，输出摘要与输入一致。

### 6.5 任务和日志

#### AC-JOB-01 合法创建

AVAILABLE 输入和合法参数创建任务返回 201/QUEUED，数据库、工作流和审计三者关联同一 jobId。

#### AC-JOB-02 Schema 校验

缺失必填、类型错误、附加禁用字段分别返回 422 和准确字段路径，不能启动工作流。

#### AC-JOB-03 幂等

相同用户、路由、Idempotency-Key 和请求重复提交返回同一任务；同键不同请求返回 409。

#### AC-JOB-04 能力匹配

任务只分配给同企业并声明所需能力的 Agent；其他企业即使空闲也不能领取。

#### AC-JOB-05 原子分配

两个 Agent 并发领取同一任务时只有一个成功，任务只产生一个有效 Lease。

#### AC-JOB-06 临时授权

Lease 创建后才签发输入/输出授权；Lease 失效后不能完成任务，暂存结果不登记为 Artifact。

#### AC-JOB-07 取消

QUEUED 任务立即 CANCELED；RUNNING 任务 10 秒内收到取消命令，最终 CANCELED；重复取消幂等。

#### AC-JOB-08 超时

任务达到 timeout 后进入 TIMED_OUT，Agent 进程被终止；可重试时产生新 Attempt，旧日志保留。

#### AC-JOB-09 失败重试

第一次失败且 maxAttempts=2 时重新排队并产生 attemptNo=2；两次失败后 Job 进入 FAILED。

#### AC-JOB-10 输出登记

Agent 成功回报后服务端 Head/摘要校验输出；校验成功才创建 AVAILABLE Artifact 并将 Job 置为 SUCCEEDED。

#### AC-LOG-01 顺序

日志按序列号展示；重复批次不产生重复行；缺口被识别并要求 Agent 重发或标记缺失。

#### AC-LOG-02 实时性

在正常网络下，Agent 写出日志到浏览器可见 P95 ≤3 秒。

#### AC-LOG-03 断线补拉

浏览器断线 1 分钟后重连，不丢日志且不重复显示；任务状态与详情 API 一致。

#### AC-LOG-04 限制和脱敏

超过 64 KB 单条日志被截断/拒绝并记录指标；符合 Token、密码、Authorization 规则的内容被掩码。

#### AC-LOG-05 失败诊断

失败页面展示标准 errorCode 和诊断 ID，不展示堆栈中的密钥、本地绝对敏感路径或内部 SQL。

## 7. 安全验收

| ID | 测试 | 通过条件 |
|---|---|---|
| AC-SEC-01 | 跨企业 IDOR | 遍历项目、资产、任务和 Agent UUID 均返回 404，无元数据泄露 |
| AC-SEC-02 | OWASP API Top 10 | 无 Critical/High；Medium 有修复计划且不影响发布安全基线 |
| AC-SEC-03 | 上传攻击 | 路径穿越、伪造 MIME、超大文件、恶意压缩包不能越过状态和配额控制 |
| AC-SEC-04 | 注入 | SQL/命令/模板/日志注入测试无执行或结构破坏 |
| AC-SEC-05 | 密钥扫描 | Git 历史、镜像、前端包、日志和错误响应无真实密钥 |
| AC-SEC-06 | 供应链 | 生产镜像有 SBOM 和签名，无未豁免 Critical/High 漏洞 |

## 11. 端到端发布验收

### AC-E2E-01 标准链路

自动化脚本连续执行 20 次：

1. 创建测试用户并验证邮箱。
2. 创建企业、邀请工程师并接受。
3. 创建项目。
4. 上传 100 MB 随机文件，记录 SHA-256。
5. 确认资产 AVAILABLE。
6. 创建 `artifact.copy.v1` 任务。
7. 等待 Agent 领取并查看实时日志。
8. 等待任务 SUCCEEDED。
9. 下载结果并验证 SHA-256 与输入一致。
10. 查询审计事件，确认关键步骤齐全。
11. 删除测试业务数据并确认策略正确执行。

通过条件：成功率 ≥95%；失败必须有可诊断错误，不能出现数据串租、重复任务、无主临时凭证或状态永远卡住。

## 12. 缺陷等级与发布规则

| 等级 | 定义 | 发布规则 |
|---|---|---|
| Blocker | 数据泄露、数据损坏、认证绕过、核心链路不可用 | 必须清零 |
| Critical | 主要功能无替代方案、任务重复执行、恢复失败 | 必须清零 |
| Major | 部分用户受影响但有明确绕行 | 原则上清零，例外需产品和技术负责人书面接受 |
| Minor | UI、文案或低频非核心问题 | 可进入已知问题并排期 |
