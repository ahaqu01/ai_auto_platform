> Owner：平台架构 / API / 安全 / QA

## 1. 范围

本文是 M2-01 的 API、数据库、威胁和恢复基线。它约束 M2-02～08，但不代表这些工作包已经实现。

## 2. 数据库草案

`upload_sessions` 至少包含：`id`、`organization_id`、`project_id`、`created_by`、`display_name`、`object_key`、`expected_size`、`expected_sha256`、`declared_content_type`、`status`、`storage_upload_id`、`reserved_bytes`、`expires_at`、`completed_at`、`version` 和时间戳。

`artifacts` 至少包含：`id`、`organization_id`、`project_id`、`created_by`、`display_name`、`object_key`、`bucket_alias`、`size_bytes`、`expected_sha256`、`verified_sha256`、`declared_content_type`、`detected_content_type`、`integrity_status`、`security_scan_status`、`status`、`retention_until`、`deleted_at`、`version` 和时间戳。

关键约束：

- `object_key` 全局唯一且不可修改；业务表保存受控 `bucket_alias`，不接受请求传入 bucket。
- `expected_size` 范围为 1～20 GiB；SHA-256 固定 64 位小写十六进制。
- 活动会话按组织计数并预留字节；终态释放预留。
- 两表均带 `organization_id` 并启用 FORCE RLS；项目外键和租户一致性由复合约束或触发器防止漂移。
- 状态转换使用版本/条件更新，禁止无条件覆盖并发结果。

## 3. API 草案

后续实现保持以下资源语义：

- `POST /projects/{projectId}/upload-sessions`：创建会话；请求仅含展示名、大小、SHA-256 和声明类型。
- `POST /upload-sessions/{id}/parts:sign`：按受控 part number 范围签发短期 URL。
- `POST /upload-sessions/{id}:complete`：提交有序分片清单并触发完成/验证。
- `POST /upload-sessions/{id}:abort`：幂等取消。
- `GET /upload-sessions/{id}`：返回脱敏状态，不返回长期凭据。
- `GET /projects/{projectId}/artifacts`、`GET /artifacts/{id}`：仅返回当前租户与项目可见资产。
- `POST /artifacts/{id}:download-url`：只对 AVAILABLE 资产签发默认 10 分钟短期 URL。
- `DELETE /artifacts/{id}`：软删除并进入异步物理清理。

所有写接口使用 Idempotency-Key；版本敏感操作使用 If-Match。错误码至少固定：`PROJECT_ARCHIVED`、`UPLOAD_TOO_LARGE`、`QUOTA_EXCEEDED`、`UPLOAD_EXPIRED`、`UPLOAD_STATE_CONFLICT`、`OBJECT_MISSING`、`SIZE_MISMATCH`、`CHECKSUM_MISMATCH`、`ARTIFACT_NOT_AVAILABLE` 和 `STORAGE_UNAVAILABLE`。

## 4. 威胁模型

| 威胁 | 强制控制 | 验收证据 |
|---|---|---|
| 客户端注入 Key/bucket 或路径穿越 | DTO 禁止额外字段；服务端随机 Key | hostile DTO/OpenAPI 测试 |
| Key 覆盖与重放 | 随机唯一 Key；条件创建；幂等键 | 并发与重复请求测试 |
| 跨租户读取/写入 | 应用授权 + FORCE RLS + 404 隐藏 | A/B/无租户 PostgreSQL 矩阵 |
| 归档竞态 | 授权后在提交事务复核项目状态 | 归档/完成并发测试 |
| 预签名 URL 泄漏或超权 | 短 TTL、单对象/操作、日志脱敏 | 日志扫描与策略检查 |
| 超大文件/配额穿透 | 会话前硬限制、预留字节、并发计数 | 20 GiB 边界和并发测试 |
| 摘要/类型欺骗 | 完整 SHA-256、Head、类型嗅探 | mismatch 与伪装类型测试 |
| 压缩炸弹/恶意内容 | 不在 API 解压；隔离扫描；资源限制 | 隔离与超时测试 |
| OSS 回调伪造 | 回调不作为完成依据；主动 Head/验证 | 伪造回调测试 |
| 孤儿或缺失对象 | Reconciler、不可变 Key、指标/审计 | 对账故障注入 |
| 凭据进入日志/Git | 受控注入、结构化脱敏、secret scan | CI 扫描和日志断言 |

## 5. 失败恢复矩阵

| 场景 | 持久状态 | 恢复方式 |
|---|---|---|
| DB 创建会话成功、存储初始化失败 | PENDING_UPLOAD/FAILED | 同幂等键重试或安全终止并释放配额 |
| 存储初始化成功、DB 保存失败 | 无可见会话 | 清理临时 upload；对账兜底 |
| 分片上传中断 | UPLOADING | 会话有效期内重签并续传 |
| Complete 成功、DB 更新失败 | COMPLETING | 同 Key/Upload ID 幂等 Head 后收敛 |
| DB 记录完成、对象缺失 | VERIFYING/FAILED | 重试 Head；达到阈值失败并告警 |
| 摘要或大小不匹配 | QUARANTINED | 禁止下载/任务引用，受控清理 |
| 重复或并发完成 | 原成功结果或 409 | 唯一约束 + 条件更新，只产生一个资产 |
| 物理删除失败 | DELETING | 指数退避重试，对账直到 DELETED |
| 孤儿对象 | 无业务记录 | 宽限期后按受控 prefix 清理并审计 |

## 6. 存储环境基线

开发环境使用 MinIO；OSS Staging 固定在 `cn-hangzhou`，公开 endpoint 为 `https://oss-cn-hangzhou.aliyuncs.com`，私有 Bucket 为 `aiautoplatform`。M2-02 必须验证 Bucket 地域、私有访问、最小权限、CORS、生命周期和版本策略。

长期 AccessKey 不属于应用配置契约。推荐服务器角色或 RAM + STS；凭据只由受控密钥通道注入，不进入数据库、浏览器持久存储、Markdown、Git、CI 输出或命令行参数。

## 7. 验收测试骨架

- 生成 100,000 个 Key，格式正确、无重复且不含输入数据。
- 双状态机逐条验证允许/禁止转换以及终态不变性。
- 1 B、20 GiB 接受；0、20 GiB+1 拒绝；1 GiB 执行真实数据面 E2E。
- A/B/无租户、角色、归档、删除和不可用资产矩阵。
- 正确/错误 SHA-256、大小错误、对象缺失、类型伪装和隔离。
- DB/存储双向故障、重复/并发完成、取消、过期、清理与对账。
- 全量日志、审计 payload 和异常输出执行秘密/预签名泄漏扫描。
