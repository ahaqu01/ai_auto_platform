## 1. 审计结论

现有设计的总体方向正确：模块化单体、PostgreSQL 事实源、Temporal 长流程、OSS 直传、Agent 主动出站、Job/Attempt/Lease、Transactional Outbox 和多租户隔离均适合第一阶段。

审计发现 10 项需要在编码前修正的重要缺陷，其中 7 项属于阻断级设计问题，若不修正可能造成任务重复执行、资产摘要不可信、长任务传输失败、身份协议混乱、租户上下文泄漏或灾备不完整。本文给出统一修订条款。

## 3. 统一修订裁决

新增并覆盖详细设计中的架构裁决：

| 编号 | 修订裁决 |
|---|---|
| DD-015 | Web 统一采用 BFF 会话模式；BFF 持有 Keycloak Token，浏览器只保存同站 HttpOnly Session Cookie |
| DD-016 | 浏览器 SHA-256 只作为预期值，资产必须由可信服务或受信 Agent 重新计算后才能 AVAILABLE |

## 4. AUD-01：Temporal 等待模型修订

### 4.1 原缺陷

V1.0 伪代码使用 `wait_for_attempt_terminal` 长 Activity，并设置长 `start_to_close_timeout` 和 Heartbeat。该方式会让 Activity 长时间轮询业务数据库，增加 Worker 资源占用，并把工作流状态与数据库轮询耦合。

### 4.2 修订方案

Workflow 通过 Signal/Update 接收 Attempt 状态变化，同时使用 durable timer 处理超时。API 在数据库事务提交后，通过 Outbox 消费者向固定 Workflow ID 发送幂等 Signal。Signal 丢失或乱序时，以数据库短查询 Activity 进行校准。

```python
@workflow.defn
class JobWorkflow:
    attempt_event = None

    @workflow.signal
    async def attempt_changed(self, event):
        # 只接受更高 attempt_no / event_version
        if is_newer(event, self.attempt_event):
            self.attempt_event = event

    @workflow.run
    async def run(self, job_id: str):
        while True:
            job = await workflow.execute_activity(
                load_job, job_id, start_to_close_timeout=30
            )
            if job.is_terminal:
                return

            assigned = await workflow.execute_activity(
                try_assign_agent, job_id, start_to_close_timeout=30
            )
            if not assigned:
                await workflow.sleep(next_backoff())
                continue

            self.attempt_event = None
            try:
                await workflow.wait_condition(
                    lambda: self.attempt_event is not None,
                    timeout=job.timeout_seconds + 60,
                )
            except asyncio.TimeoutError:
                pass

            outcome = await workflow.execute_activity(
                reconcile_attempt_state,
                assigned.attempt_id,
                start_to_close_timeout=30,
            )
            decision = await workflow.execute_activity(
                finalize_or_retry,
                args=[job_id, outcome],
                start_to_close_timeout=30,
            )
            if decision.job_terminal:
                return
```

规则：

- Workflow 不直接访问 PostgreSQL。
- Activity 应是短事务，不以轮询维持生命周期。
- Signal Payload 包含 `job_id`、`attempt_id`、`attempt_no`、`event_version` 和状态。
- 数据库仍是事实源，Signal 只是唤醒和加速机制。
- Workflow ID 固定为 `job/{job_id}`，Signal 发送至少一次且幂等。

## 5. AUD-02：资产完整性修订

### 5.1 原缺陷

浏览器计算的 SHA-256 不可信；Multipart ETag 也不是文件 SHA-256。允许“抽样验证”后标记 AVAILABLE 会破坏资产证据链。

### 5.2 修订状态与字段

`artifacts` 增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| expected_sha256 | char(64) | 客户端声明，不可信 |
| verified_sha256 | char(64) | 可信验证器计算，可空 |
| integrity_status | varchar(20) | `PENDING/VERIFIED/MISMATCH/FAILED` |
| integrity_verified_at | timestamptz | 验证完成时间 |
| verified_by | varchar(20) | `CLOUD_VERIFIER/TRUSTED_AGENT` |

只有 `integrity_status=VERIFIED` 且安全扫描通过的资产才能进入 `AVAILABLE`。

### 5.3 验证流程

1. OSS Complete 后 HeadObject 校验对象键、大小和 OSS CRC64。
2. Artifact 创建为 `VERIFYING/PENDING`。
3. 同地域 Integrity Verifier 通过 OSS 内网 Endpoint 流式读取对象并计算完整 SHA-256。
4. 同时执行病毒扫描和文件类型嗅探。
5. 摘要一致则写 `verified_sha256` 并置 AVAILABLE；不一致进入 QUARANTINED。
6. 读取失败可重试，达到阈值后 FAILED，并保留诊断记录。

禁止以抽样验证、Multipart ETag 或客户端声明代替完整摘要。大文件成本通过项目配额、并发队列、内网 Endpoint 和计量控制。

## 6. AUD-03：长任务传输授权修订

初始命令只携带短期授权。新增接口：

```text
POST /agent-api/v1/attempts/{attemptId}:refresh-transfer-grant
```

请求必须同时校验：

- mTLS 证书对应的 Agent；
- Attempt 当前分配给该 Agent；
- Lease Token；
- `fencing_epoch`；
- Lease 未过期；
- Attempt 非终态且没有不可逆取消。

响应只包含该 Attempt 输入对象的 GET 和输出暂存前缀的 PUT/Multipart 最小权限，默认 20—30 分钟。不得返回 Bucket 列举、删除或其他项目权限。刷新限流并写安全审计。

## 7. AUD-04：Lease fencing 修订

### 7.1 数据库字段

`job_attempts` 增加 `fencing_epoch bigint not null`。每次为同一 Job 创建新 Attempt 时取 `previous_epoch + 1`，由 Job 行锁保证单调性。

`job_leases` 增加：

```text
fencing_epoch bigint not null
lease_token_hash bytea not null
```

### 7.2 写请求规则

Agent 的 accept、renew、logs、refresh grant、complete、fail 和 cancel-ack 都必须携带 epoch。服务端校验：

```text
certificate.agent_id == attempt.agent_id
request.epoch == attempt.fencing_epoch == lease.fencing_epoch
lease_token HMAC matches
lease.expires_at > database_now()
attempt.status allows operation
```

任何旧 epoch 请求返回 `LEASE_EXPIRED`，不得更新日志、输出或状态。服务端以数据库时间为准，不相信 Agent 时间。

## 8. AUD-05：身份体系修订

### 8.1 唯一事实源

- 密码、MFA、登录失败、邮箱验证和 OIDC 会话：Keycloak。
- 用户业务投影、平台禁用状态、语言和时区：PostgreSQL。
- 企业/项目角色：PostgreSQL。
- 浏览器会话：BFF 服务端会话；浏览器仅持有同站 HttpOnly Cookie。

平台数据库不保存或校验密码。`users.password_hash` 从新建 Schema 中删除；若已有迁移包含该字段，保持 NULL 并创建后续迁移删除，禁止写入。

### 8.2 API 语义

原 `/auth/register`、`/auth/login`、`/auth/forgot-password`、`/auth/reset-password` 可以保留为前端语义入口，但只负责发起/跳转 Keycloak Flow，不接受第二套密码逻辑。

SSE 与 REST 都使用 BFF Session Cookie；所有修改请求校验 CSRF Token、Origin 和 SameSite 策略。不得把 Refresh Token 放入 LocalStorage。

## 9. AUD-06：RLS 与连接池修订

RLS Policy 使用：

```sql
current_setting('app.organization_id', true)
```

当上下文为空时默认拒绝，不抛出带内部信息的异常。每个业务事务：

```sql
BEGIN;
SET LOCAL app.organization_id = :org_id;
SET LOCAL app.actor_id = :actor_id;
-- query/update
COMMIT;
```

禁止 Session 级 `SET`。连接池归还前强制 rollback，并在测试环境断言租户变量为空。公开无企业接口只能访问无租户表。平台后台使用独立数据库角色和独立 Repository，不允许普通请求通过参数切换为后台角色。

新增测试：同一物理连接依次处理企业 A、企业 B 和无租户请求，三者数据必须严格隔离。

## 10. AUD-07/AUD-12：完整灾备与证书修订

### 10.1 必须备份和演练的状态

| 系统 | 备份/恢复要求 |
|---|---|
| 业务 PostgreSQL | 自动备份、WAL/PITR，RPO≤15 分钟、RTO≤2 小时 |
| Keycloak 数据库 | 独立备份；Realm/Client/Flow/Theme 使用 IaC 导出 |
| Temporal 数据库 | 持久化和 Visibility 分别备份，验证版本兼容和 Workflow 恢复 |
| OSS | 版本控制、正式资产延迟删除、审计归档对象锁 |
| 在线中间 CA | KMS/HSM 或加密备份，双人恢复；离线根 CA 独立保管 |
| Vault/KMS | 策略、Secret 元数据和恢复流程；明文 Secret 不进文档/仓库 |
| Agent 吊销状态 | 与 Agent Registry 一起恢复并验证旧证书仍被拒绝 |

### 10.2 证书策略

- Agent 证书有效期 30 天，剩余 10 天自动轮换。
- Agent Gateway 每分钟拉取增量吊销列表；紧急禁用 2 分钟内生效。
- 证书 SAN 使用 `spiffe://.../organizations/{org}/agents/{agent}`。
- Agent 私钥本地生成且不可导出到任务容器。
- CA 恢复演练不能通过“允许全部旧证书”简化。

## 11. AUD-08：容量投影修订

`agents.active_jobs` 只是查询缓存，不能作为唯一调度事实。

- 调度事务同时查询该 Agent 的非终态 Attempt 数量。
- 每分钟 Reconciler 按 Attempt 重算 `active_jobs`。
- Agent 上线时将本地活跃 Attempt 与云端双向对账。
- 云端未知但本地仍运行的进程先冻结并查询，不直接继续上传。
- 数据库存在但 Agent 不认识的 Attempt 在 Lease 到期后 LOST。

## 12. AUD-09：SSE 认证修订

统一使用基于 `fetch` 的 SSE 客户端，携带 BFF Session Cookie，并执行 Origin/CSRF 策略。不使用需要把 Bearer Token 放入 LocalStorage 的实现，也不把原生 EventSource 作为唯一方案。

重连继续使用 `Last-Event-ID`；服务端每 15 秒心跳，连接最长 30 分钟，单用户/项目设置连接上限。

## 13. AUD-10：阿里云地域与网络修订

### 13.1 地域原则

- ECS、RDS、Redis、OSS、日志和备份主链路优先在同一地域。
- 应用访问 OSS 必须使用对应地域的内网 Endpoint；浏览器直传使用公网/加速 Endpoint。
- 配置项必须拆分为 `OSS_PUBLIC_ENDPOINT` 和 `OSS_INTERNAL_ENDPOINT`，并在启动时校验 Bucket 地域。
- 禁止因复制粘贴错误混用华北、华东等不同地域 Endpoint。
- 跨地域复制只用于经评审的灾备，不参与在线任务链路。

### 13.2 配置启动检查

服务启动时调用 OSS BucketInfo/Region API，确认 Endpoint、Bucket 和期望 Region 一致；不一致则生产环境拒绝启动。

任何云账号、密码、AccessKey、SSH 密码都不得出现在 Markdown、代码、镜像、CI 日志或命令行历史中。已有暴露凭证必须轮换后再用于部署。

## 14. AUD-11：输出提交事务修订

OSS Head、Copy 和摘要计算是外部调用，禁止放在持有 Job/Attempt 行锁的长事务中。采用三段式：

1. **冻结事务**：校验 Agent、Lease、epoch；保存输出 Manifest；Attempt 进入内部 `VERIFYING_OUTPUT`。
2. **外部验证**：无数据库长锁地执行 Head、可信摘要和必要 Copy；操作使用不可变 Key，能够幂等重试。
3. **最终事务**：再次校验 Attempt、epoch 和取消状态；创建 Artifact/JobOutput；Job/Attempt 进入 SUCCEEDED；撤销 Lease；写审计与 Outbox。

Reconciler 扫描超时的 `VERIFYING_OUTPUT`，继续验证或收敛为 FAILED，禁止永久中间态。

## 18. 新增验收场景

| ID | 场景 | 通过条件 |

| AC-REV-01 | 伪造客户端 SHA-256 | Artifact 进入 QUARANTINED，不得 AVAILABLE |

| AC-REV-10 | OSS Endpoint 配置到错误地域 | 生产服务拒绝启动并产生明确告警 |

## 20. 仍需业务确认的非技术问题

以下问题无法由技术设计单方面决定，进入正式商用前需要公司确认：

- 首批正式支持的行业场景、模型族和芯片矩阵；
- 企业数据默认保留期限和删除 SLA；
- 客户是否允许云端完整性扫描，还是要求本地可信 Agent 验证；
- 私有化部署版本是否第一阶段同步交付；
- 实机验收指标的法律效力、责任边界和报告签署方式；
- 开源组件、模型权重、数据集和厂商 SDK 的商业再分发权限；
- 阿里云正式地域、备案主体、域名、等保和个人信息处理要求。

这些项目不阻塞基础代码骨架，但会影响生产配置、合同、数据流和商用发布。
