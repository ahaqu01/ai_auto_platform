# M2 资产与对象存储闭环实施计划

- 状态：COMPLETED / ACCEPTED
- 启动日期：2026-09-01
- 基线：`m1-accepted`（`c81a005`）
- 工作分支：`codex/m2-assets-storage`
- Owner：产品 / 平台架构 / API / Web / 安全 / QA

## 目标

建立从资产元数据、受控上传、对象校验、授权下载到失败恢复和对账清理的最小闭环。M2 不引入 Agent 执行、任务编排或任意用户代码运行。

## 强制设计原则

1. 对象 Key 只能由服务端生成，客户端不得提供最终 Key 或存储桶。
2. 数据库是资产业务状态源，对象存储是字节载体；两者失败必须可幂等恢复和对账。
3. 所有用户写入遵循 ADR-0005：项目归档后返回 `409 PROJECT_ARCHIVED`。
4. 下载授权同时验证组织、项目、资产状态和调用者权限，不以预签名 URL 代替授权。
5. 预签名 URL、临时凭证、访问密钥和分片令牌不得进入日志、审计 payload 或异常文本。
6. 审计、幂等和 Outbox 复用 M1-08 基线；RLS 复用 M1-09 基线。
7. MinIO 开发 E2E 与阿里云 OSS Staging E2E 分开验收，不以接口模拟替代真实兼容性证据。

## 工作包顺序

### M2-01：对象 Key 与威胁模型

定义资产状态机、服务端 Key 规则、配额/大小边界、摘要算法、内容类型、越权模型、归档策略和失败矩阵。输出 ADR、API 草案、数据库草案和测试矩阵；本工作包通过前不实现上传接口。

### M2-02：对象存储适配端口

建立与厂商无关的存储端口、MinIO 适配器和 OSS 适配器契约；覆盖错误归一化、超时、重试、取消和日志脱敏。

### M2-03：上传会话

实现资产占位、服务端 Key、上传会话状态、大小/类型/摘要约束、幂等创建、过期与取消。

### M2-04：Multipart

实现分片初始化、上传授权、分片登记、重试、断点续传、取消和并发完成保护。

### M2-05：完成校验

校验对象存在性、大小、摘要和分片清单；用显式状态机处理 DB 成功/OSS 失败和 OSS 成功/DB 失败。

### M2-06：下载授权

实现项目/资产授权、短期预签名 URL、响应头约束、审计及已删除/隔离对象拒绝。

### M2-07：清理与对账

实现过期会话、孤儿对象、缺失对象和失败删除的扫描、补偿、指标与审计。

### M2-08：Web 上传闭环

实现选择、进度、暂停/恢复、取消、失败重试、摘要错误和授权下载体验；不得在浏览器持久化长期存储凭据。

## 总体验收矩阵

- 文件规模：1 KB、100 MB、1 GB。
- 传输：单段、Multipart、断点续传、重复分片、取消、过期。
- 完整性：正确摘要、摘要错误、大小错误、对象缺失。
- 一致性：DB 成功/OSS 失败、OSS 成功/DB 失败、重复完成、并发完成。
- 安全：跨租户 A/B/无租户、归档项目、已删除资产、越权下载、日志凭据扫描。
- 兼容性：MinIO 开发 E2E、阿里云 OSS Staging E2E。
- 治理：审计、幂等、Outbox、RLS、清理与对账证据。

## 版本管理与门禁

- 每个 M2 工作包使用独立提交和独立验收记录；禁止把 01～08 压成一个大提交。
- 每个提交至少执行 `git diff --check`、相关单测、PostgreSQL 集成测试、文档检查和 CI。
- 涉及存储凭据、预签名、下载授权时必须执行安全扫描和日志泄漏专项测试。
- M2-01 只允许设计和测试骨架；设计门禁通过后方可进入 M2-02。
- 只有 M2-01 至 M2-08 全部通过、真实 MinIO/OSS 证据齐全并完成四方签字后，才能创建 `m2-accepted`。
