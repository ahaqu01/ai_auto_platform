## 2. 动态执行顺序

1. 等待远端仓库期间，先执行 M0R-04，并继续执行“验收标准 → 预期失败测试 → 实现 → 验证”。
2. 随后执行 M0R-05、M0R-06、M0R-07。
3. 用户提供私有远端仓库后，立即插入 M0R-01、M0R-02、M0R-03A；不得晚于 M1 开始。
4. M0R-03 只有补齐独立评审、CI 和 Staging 证据后才能逐级晋升。

## 3. OpenAPI 门禁补强

CI 必须执行：

1. `.venv/bin/python scripts/export_openapi.py --check`。
2. `.venv/bin/pytest apps/api/tests/test_openapi_contract.py -q`。
3. PR 快照相对目标分支快照的兼容性检查。
4. 对破坏性变更输出差异、版本策略和批准记录。

## 4. 历史迁移治理规则

- 已部署或已在共享环境执行的迁移视为不可变，不因纯格式原因追溯改写。
- 当前两份历史迁移的 Ruff 格式差异登记为基线债务，不阻断 M0R-04。
- 新迁移必须在首次部署前通过格式、静态检查、升级、降级再升级验证。
- CI 格式检查应区分应用源码与不可变历史迁移；迁移仍必须接受语法、导入和行为检查。

## 5. 下一阶段准入

M0R-04 开发前必须先形成：

1. 配置项清单与环境分级规则。
2. 稳定编号的验收标准。
3. 启动失败、默认值误用和 Compose 告警测试用例。
4. 密钥、回滚、开发兼容性风险说明。
5. 实现前的预期失败证据。
