# ADR-0006：资产对象标识、生命周期与完整性

- 状态：Accepted
- 决策日期：2026-09-02
- 决策编号：M2-01
- Owner：平台架构 / API / 安全

## 背景

既有 PRD、架构和 ER 草案对上传会话、资产状态、对象 Key 和摘要验证存在口径差异。对象存储一旦进入实现，Key 兼容性、状态收敛和安全边界很难低成本修改，因此必须在 M2 数据库和 API 开发前形成唯一决策。

## 决策

### 对象身份

最终对象 Key 由服务端使用密码学安全随机数生成，规范格式为 `v1/o/{32位小写十六进制值}`。数据库对 `object_key` 建立全局唯一约束；对象创建必须使用“不存在才创建”语义，禁止覆盖。

Key 不包含组织 ID、项目 ID、用户 ID、邮箱、原始文件名、日期、客户端路径或其他可推断业务归属的信息。展示文件名只保存在数据库中并单独进行长度、控制字符和响应头编码校验。Bucket 和 Key 均不接受客户端指定。

### 双状态机

上传会话状态：`PENDING_UPLOAD`、`UPLOADING`、`COMPLETING`、`COMPLETED`、`ABORTED`、`EXPIRED`、`FAILED`。前三者为活动状态，后四者为终态；失败重试创建新会话，幂等重放可返回已经成功的原结果。

资产状态：`VERIFYING`、`AVAILABLE`、`QUARANTINED`、`FAILED`、`DELETING`、`DELETED`。只有 `AVAILABLE` 可签发下载 URL；AVAILABLE 只是后续执行消费的必要条件，不能代替内容安全门禁。M3 训练、解压和设备执行消费必须另行要求扫描 CLEAN 或有明确可审计的安全豁免；NOT_REQUIRED 不得当作 CLEAN。物理删除失败不回退业务可见性，由 `DELETING` 和 Reconciler 收敛。

### 完整性与内容安全

客户端提交的小写十六进制 SHA-256 是不可信的 `expected_sha256`。服务端验证器必须经内网 endpoint 完整流式读取对象并计算 `verified_sha256`；不得用 Multipart ETag、客户端声明或抽样代替。大小、对象存在性和存储侧校验信息同时验证。

内容嗅探或恶意内容检测失败进入 `QUARANTINED`。病毒扫描能力允许在 M2 分阶段接入，但未部署扫描器时必须由显式环境策略决定是否阻断 AVAILABLE，禁止静默视为“已扫描”。生产策略和豁免必须可审计。

### 边界与授权

单文件契约上限为 20 GiB；1 GiB 是强制 E2E 样本。创建会话前检查大小、并发上传和存储预留配额，结束、取消和过期均释放预留量。

授权顺序为：身份 → 组织/项目可见性 → 项目角色 → 资源状态/归档状态。无权或跨租户主体保持 403/404 语义；已授权主体对归档项目业务写入返回 `409 PROJECT_ARCHIVED`。预签名 URL 不是授权凭证的替代品，只能在授权成功后短期签发。

### 跨系统一致性

数据库是业务状态源，对象存储是字节载体。原则上网络调用不放在持有业务行锁的长事务中。现有 Multipart 初始化及 completion 串行验证为明确实现例外：completion 先提交持久化 checkpoint，再重获上传会话行锁直到完成验证与发布，避免并发发布；大对象验证持锁成本保留为技术约束，不宣称已实现异步校验。所有外部步骤使用不可变 Key 和幂等命令；Reconciler 负责收敛超时完成、孤儿对象、缺失对象和删除失败。

2026-09-17 P2 合同修订：对外上传/下载签名为 60～900 秒，默认分别为 900/600；非法有效期在请求校验层返回 422。完成命令持久化 actor/key/manifest hash，成功重放 200、清单冲突 409、隔离错误 409 重放；仅在上传会话行锁保护下允许恢复 PROCESSING。运行时长期 RAM Key 的 STS 迁移仍须真实切换验收，不能靠计划文档关闭。

## 影响

opaque Key 降低运维可读性，但阻止业务标识泄漏并简化覆盖保护。完整 SHA-256 增加读取成本，但为任务输入建立可信完整性。双状态机增加表和转换规则，却避免上传协议状态污染资产生命周期。

## 后续约束

M2-02 的端口不得依赖具体 SDK 类型；M2-03～07 的迁移、API、RLS、审计、幂等和 Outbox 必须实现本 ADR；M2-08 不得持久化长期凭据。任何改变 Key 版本、终态或可信摘要定义的变更必须新增 ADR。
