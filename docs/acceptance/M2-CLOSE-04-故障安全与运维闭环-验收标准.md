# M2-CLOSE-04 故障、安全与运维闭环验收标准

> 状态：ACTIVE  
> 原则：代码测试、真实 PostgreSQL、真实对象存储和 Staging 运行证据缺一不可。

## A. 故障恢复矩阵

1. 分片 PUT 返回 500 或超时时，不登记伪成功；同一分片可安全重试。
2. 过期签名被拒绝，刷新签名后可继续，服务端存储上传 ID 不泄漏。
3. 重复登记同一分片幂等；不同 ETag/大小冲突被拒绝。
4. 并发 complete 只有一个有效状态转换，其余请求返回确定性的重放或冲突结果。
5. complete 响应丢失后重试，不重复生成资产或重复扣减配额。
6. 数据库提交失败不留下伪 AVAILABLE 状态；后续可安全恢复或对账。
7. HEAD 瞬时失败不误判对象缺失；真实缺失对象进入既定安全状态并有审计证据。
8. 删除失败保持 DELETING 并记录退避；远端 NOT_FOUND 作为幂等成功。
9. 孤儿保护窗口内对象不删除，超过窗口且不被会话/资产引用的对象才可删除。
10. reconcile 重复执行结果稳定，失败项遵循可观测退避，不发生双删或状态回退。

## B. 授权与状态矩阵

必须在真实 PostgreSQL 和真实对象存储环境验证：租户 A、租户 B、无租户上下文、非成员、归档项目，以及 AVAILABLE、QUARANTINED、DELETING、DELETED。跨租户读取、签名、下载、删除和维护操作均须失败关闭，且响应不得泄漏对象 Key、Bucket 或内部上传 ID。

## C. 调度与可观测性

1. 有可部署的常驻入口和一次性验收入口。
2. 多实例或重叠触发时有数据库级互斥并可观测地跳过。
3. 单轮任务有超时，异常和超时后锁必释放，循环可继续。
4. 输出运行时长和各类处理计数；失败达到阈值时输出明确告警事件。
5. 健康检查能识别长时间未成功运行，配置值有合理边界。
6. 至少一次在真实 Staging 数据库/对象存储上运行并记录清理或零差异对账结果。

## D. 敏感信息与日志

扫描 API、Web/Nginx、Keycloak、维护任务、审计和 Outbox。不得出现 OSS AK、Secret、会话 Token、Authorization/Cookie、完整预签名 URL或内部 Multipart upload ID。证据只记录“命中/未命中”、容器与时间，不复制秘密原文。

## E. 质量与版本门禁

- Ruff、专项测试、API 回归、隔离 PostgreSQL 集成测试和 CI 全部通过。
- 实现、验收记录和同名开发文档分层提交并推送。
- 测试对象、会话、临时租户和临时账号清理完成，有清单可复核。
- 任何未满足项均使结论保持 `IN PROGRESS` 或 `REJECTED`，不得以单元测试替代真实链路验收。
