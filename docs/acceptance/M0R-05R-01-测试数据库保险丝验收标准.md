# M0R-05R-01 测试数据库保险丝验收标准

> Status: READY
> Baseline: `6909d4c`
> Risk source: M0R-03 至 05 严格评审 P1-01

## 验收标准

| ID | 标准 |
|---|---|
| DBG-01 | 未提供精确 opt-in 确认值时，在建立数据库连接前拒绝 |
| DBG-02 | URL 必须为 PostgreSQL，数据库名和用户名必须以 `_test` 结尾 |
| DBG-03 | `platform`、`prod`、`production`、`live` 等非测试库全部拒绝，APP_ENV 缺失或大小写变化不能绕过 |
| DBG-04 | 连接后、任何 DDL 前核对 `current_database()`、`current_user` 与 URL 一致 |
| DBG-05 | 当前角色为 superuser 时拒绝 |
| DBG-06 | downgrade 需要第二个独立精确确认值，普通测试确认不能授权 downgrade |
| DBG-07 | 错误消息不得包含密码或完整 URL |
| DBG-08 | 本地提供专用 `platform_test` 数据库和非超级用户 `platform_test`；应用库保持不变 |
| DBG-09 | 清理目标仍只允许本次生成的 `test_<uuid>` schema |
| DBG-10 | 安全专项、允许的 PostgreSQL 测试和非破坏性全量回归通过 |

## 测试优先与暂停规则

先运行纯安全测试并取得预期失败。DBG-01 至 DBG-07 转绿前禁止连接测试数据库；downgrade 测试在 DBG-06 通过且显式授权前保持暂停。

## 版本门禁

- 基线固定为 `6909d4c`。
- 最终提交必须单一职责、可回滚，并记录提交 ID。
- 提交前执行 `git diff --check`、敏感信息扫描和工作区检查。
