# M2-08 Web 上传闭环验收标准

> 日期：2026-09-15

## 代码与功能强制项

1. 用户只能在可见组织的活动项目中创建上传；空文件和超过 20 GiB 的文件在前端拦截，后端仍为最终约束源。
2. SHA-256 必须分块读取，跨读取分块结果与标准 SHA-256 一致。
3. 文件按 Multipart 分片直传；每片使用短期预签名 URL，成功后登记 ETag 和大小，最后按序提交完整清单。
4. UI 显示摘要、上传、暂停、校验、成功、失败、取消状态及字节进度。
5. 暂停必须中止在途 PUT；恢复必须读取服务端登记分片并跳过已完成分片。
6. PUT 失败最多重试三次且每次重新签名；终态或过期会话不得继续上传。
7. 取消必须停止本地请求并调用服务端取消。

## 安全强制项

1. 前端源码、构建产物和日志不得包含长期对象存储凭据。
2. 预签名 URL 不得写入 localStorage、可序列化控制器状态或页面文本。
3. 对象存储 PUT 不携带平台 Cookie 或 Authorization；必须读取响应 ETag，缺少 CORS 暴露时给出安全错误。
4. 组织、项目、归档和跨租户权限继续以后端授权为准。

必须另行完成真实 MinIO 与阿里云 OSS 浏览器 Staging E2E，覆盖 1 KB、100 MB、1 GB、暂停恢复、取消、错误摘要和对象缺失。没有这些证据时，M2-08 可记为代码/CI 通过，但不得创建 `m2-accepted` 标签或宣称 M2 总体验收完成。
