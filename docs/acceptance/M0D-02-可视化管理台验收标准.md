# M0D-02 可视化管理台验收标准

## 1. 目标

将当前单一健康检查页升级为可用于阶段汇报和后续功能接入的管理台。页面必须准确区分“已可用”“基础能力已完成”和“规划中”，不得用静态数字伪装真实业务数据。

## 2. 范围

- 管理台整体框架：品牌区、侧边导航、顶部状态区、内容区域。
- 工作台：首页概览、工程流程、快捷入口、系统状态和近期进展。
- 业务导航：工作台、组织项目、数据资产、智能标注、训练中心、模型仓库、设备与部署、系统管理。
- 响应式适配桌面和窄屏。
- 继续使用真实 `/health/live` 数据。
- 未接入认证前，不绕过鉴权调用组织/项目 API。
- 未实现模块显示“规划中”或“即将开放”，不提供虚假操作结果。

## 3. 验收标准

### AC-01 管理台框架

- 页面具有固定品牌标识、一级业务导航、阶段标识和主内容区。
- 当前菜单具有清晰选中态。
- 窄屏下导航转换为横向可滚动区域，内容无横向溢出。

### AC-02 工作台内容

- 显示“项目工作台”和平台工程闭环说明。
- 展示数据准备、智能标注、模型训练、芯片适配、设备验证、交付部署六个流程阶段。
- 展示当前阶段能力和下一步入口，不伪造业务统计数据。
- 至少包含项目、数据资产、训练任务、设备节点四类概览卡片。

### AC-03 状态真实性

- API 状态通过 `/health/live` 实时读取。
- 请求成功显示服务名、版本和运行正常。
- 请求失败显示明确告警，不将失败渲染成正常。
- 未实现业务模块明确标记为“规划中/即将开放”。

### AC-04 可维护性与可访问性

- 菜单、流程和概览数据使用结构化数组渲染。
- 关键导航使用语义化标签并具有可读文本。
- 颜色对比、键盘焦点和移动端布局满足基本可用性。
- 不新增不必要的前端依赖。

### AC-05 自动化验证

- 测试先行，至少覆盖管理台导航、核心内容、真实健康状态和规划中标识。
- `npm test`、`npm run build`、部署静态契约与 HTTP 冒烟测试通过。
- 开发机从局域网访问首页返回 200 且包含新构建资产。

### AC-06 版本管理

- 基线提交为 `40c6ef0372d40076339b9163e9466fcc98d2e933`。
- 使用独立提交，提交后工作区干净。
- 验收通过后创建注释标签 `m0d-02-visual-console`。

## 4. 测试用例

- TC-01：App 渲染品牌、八个一级导航入口和当前阶段信息。
- TC-02：首页渲染项目工作台、四类概览、六阶段工程流程。
- TC-03：健康接口成功时展示真实服务名、版本和运行状态。
- TC-04：未实现模块带有规划状态，不产生虚假成功交互。
- TC-05：执行 Web 测试、TypeScript/Vite 生产构建。
- TC-06：重建 Web 镜像并执行局域网 HTTP 验证。
