# P0 身份认证与租户安全切片验收标准

> 阶段：P0-Auth-01  
> 范围：OIDC JWT 验证、CurrentUser、本地用户同步、企业/项目接口身份来源改造  
> 不在本切片：登录页面、Keycloak 管理界面、成员邀请与角色变更

## 1. 目标

任何受保护 API 的调用者身份只能来自服务端验证过的 Bearer JWT。客户端不得再通过查询参数或请求体声明自己的 `user_id`。OIDC 身份首次访问时应按稳定的 `issuer + subject` 同步为本地用户，并继续复用同一个本地用户。

## 2. 验收标准

| 编号 | 验收条件 | 验证方式 |
|---|---|---|
| AUTH-01 | 未携带 Authorization 访问企业或项目 API，返回 HTTP 401 | API 自动化测试 |
| AUTH-02 | Bearer Token 无效、过期、Issuer/Audience 不匹配时返回 HTTP 401，不泄露内部异常 | JWT 单元测试与 API 测试 |
| AUTH-03 | 有效令牌必须包含 `sub`，缺少时返回 HTTP 401 | JWT 单元测试 |
| AUTH-04 | 有效身份首次访问时创建本地用户，重复访问复用同一用户 | 数据库集成测试 |
| AUTH-05 | 本地用户以 `issuer + subject` 唯一定位，不能只依赖可变邮箱 | 数据库约束与集成测试 |
| AUTH-06 | 创建企业时 Owner 必须是当前令牌用户，请求体不再接收 owner_email/owner_display_name | API 契约测试 |
| AUTH-07 | 企业和项目接口不再接受 `user_id` 作为身份来源 | OpenAPI/API 测试 |
| AUTH-08 | 企业成员可访问本企业项目；非成员即使知道企业 UUID 也返回安全的 404 | 租户隔离测试 |
| AUTH-09 | 错误响应保持统一问题详情结构，并包含稳定 code 与 traceId | API 测试 |
| AUTH-10 | 原有领域测试、前端测试、Go 测试和生产构建全部回归通过 | 全量验证 |

## 3. 安全约束

1. 仅接受 `Authorization: Bearer <token>`。
2. 正式实现默认只允许 OIDC 提供方的非对称签名算法，不接受 `alg=none`。
3. 必须校验签名、过期时间、Issuer 和 Audience。
4. Token、Authorization Header 和完整 JWT 不得写入日志或错误响应。
5. Email 和 Display Name 仅作为资料字段；授权主体以 Issuer + Subject 为准。
6. 租户资源查询必须同时包含当前用户成员关系约束。

## 4. 测试先行规则

本切片必须按以下顺序实施：

1. 提交本验收标准。
2. 编写身份认证、用户同步和租户隔离测试。
3. 在没有实现时运行测试，记录预期失败。
4. 完成最小实现使新增测试通过。
5. 执行后端全量测试、Ruff、数据库迁移、前端测试与构建、Go 测试。

## 5. 完成定义

只有 AUTH-01 至 AUTH-10 全部通过，并且数据库迁移可在真实 PostgreSQL 上成功升级和降级检查后，本切片才算完成。
