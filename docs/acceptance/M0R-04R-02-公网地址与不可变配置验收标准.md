## 范围

本任务收紧生产/预发布环境中的公网 OIDC 与 OSS 地址策略，建立可复用的运行时 DNS/重定向校验，并冻结构造完成的 Settings。数据库、Redis、Temporal 和 OSS internal endpoint 继续按内网依赖处理，不要求使用公网地址。

## 验收条件

1. `keycloak_issuer` 与 `oss_public_endpoint` 的 IP 字面量必须是全局可路由地址；loopback、private、link-local、unspecified、reserved、multicast 和非全局特殊地址全部拒绝。
2. 已知云元数据主机名必须拒绝，至少覆盖通用 metadata 名称、Google 与阿里云元数据入口。
3. `oss_internal_endpoint` 允许 RFC1918 私网地址，体现 public/internal 策略分离；既有结构和本机回环保护不得退化。
4. 公网域名在 Settings 构造阶段不做外部 DNS 查询，避免启动过程依赖不稳定网络；运行时出站前必须解析并确认全部结果均为全局地址。
5. 运行时策略必须拒绝解析到敏感地址的域名、空解析结果及跳转到敏感地址的重定向；合法公网解析与合法公网重定向允许。
6. OIDC JWKS 默认客户端必须接入运行时公网策略，初始 URL 与每次重定向均执行校验。
7. Settings 构造后不可修改，修改字段必须失败。
8. local/test 环境仍允许显式开发配置，生产/预发布环境的原有必填、结构、TLS 和弱凭据保护继续通过。
9. 配置和网络策略错误不得回显密钥、口令或完整敏感配置值。
10. 专项测试、API 全量测试、Ruff、OpenAPI、Web、Agent、Compose 回归通过；形成独立提交及 `m0r-04r-02-implemented` 标签，提交后工作区干净。

## 非目标与风险边界

- 本任务不为尚未实现的 OSS SDK 请求链路虚构网络调用，只提供并验证同一可复用策略。
- DNS 校验可降低常见 SSRF 与重定向风险，但校验与连接之间仍可能存在 DNS rebinding/TOCTOU 窗口；若未来接入高风险通用 URL 抓取，应使用固定解析结果连接或受控出站代理。
- Staging、CI 连续成功和安全签字仍属于后续 `REVIEWED/VERIFIED_STAGING/ACCEPTED`，本任务不得宣称达到这些状态。
