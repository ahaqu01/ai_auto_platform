# M2-05 完成与强校验验收标准

> 状态：ACTIVE  
> 日期：2026-09-11

## 功能与一致性

- 完成请求必须携带 16～128 字符 Idempotency-Key 和唯一、升序的完整分片清单。
- 分片清单与登记记录、ETag、分片顺序及登记总大小完全一致后才可调用存储 Complete。
- 外部调用前持久化 `COMPLETING`；重复或恢复请求不会产生第二个资产。
- OSS 已完成而 DB 未落库时，能够通过 Head 和流式校验继续收敛。
- 成功后会话为 COMPLETED，预约容量为 0，资产唯一且为 AVAILABLE。

## 完整性与安全

- 必须完整流式读取对象计算 SHA-256；禁止使用 Multipart ETag、客户端值或抽样代替。
- 对象缺失、大小不符、摘要不符分别返回稳定错误码。
- 大小/摘要不符的对象必须进入 QUARANTINED，不可成为 AVAILABLE。
- `artifacts` 具备唯一约束、检查约束、租户外键和 FORCE RLS。
- 公开 DTO、审计、Outbox 和日志不得包含对象 Key、远端 Upload ID、长期凭据或预签名 URL。

- PostgreSQL 全迁移、回滚、RLS 和跨租户验收通过。
- 独立实现提交与独立验收证据提交均推送，GitHub Actions 成功。
