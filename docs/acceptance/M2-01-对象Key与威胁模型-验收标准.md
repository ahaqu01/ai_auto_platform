# M2-01 对象 Key 与威胁模型验收标准

- 状态：CURRENT
- Owner：QA / 安全 / 平台架构
- 日期：2026-09-02

## 强制标准

1. 上传会话与资产双状态机分别定义允许转换、终态和并发策略。
2. 对象 Key 只由服务端生成，不包含业务标识或用户输入，Bucket 不接受客户端选择。
3. 单文件 20 GiB 上限、配额预留/释放、摘要、内容类型和安全扫描策略有唯一口径。
4. 完整 SHA-256 是 AVAILABLE 的可信完整性门禁；客户端值、抽样和 Multipart ETag 不可替代。
5. 授权、跨租户隐藏、ADR-0005 归档语义和下载授权顺序明确。
6. 威胁模型覆盖 Key 注入、覆盖、跨租户、归档竞态、预签名泄漏/重放、资源耗尽、内容欺骗、孤儿对象和凭据泄漏。
7. DB/对象存储双向失败、并发完成、取消、过期、删除和对账均有可幂等恢复策略。
8. DB/API 草案可直接指导 M2-02～07，不依赖具体厂商 SDK 类型。
9. MinIO 与 OSS 分开验收；OSS 非秘密配置可记录，任何 AccessKey/Secret 不得进入交付物或 Git。
10. 开发文档、ADR、设计基线、验收记录、权威状态和 M2 计划同步更新。
11. `scripts/check_docs.py`、`git diff --check` 和完整 CI 通过。
12. 本工作包无上传 API、迁移、SDK 适配或虚假的 OSS E2E 完成声明。

## 评审问题

- 是否存在两个来源对同一状态或摘要定义给出不同答案？
- Key 是否可由文件名、组织、项目、用户或日期推断？
- 任一中间态是否可能永久停留且没有扫描/补偿路径？
- 无权主体是否能通过错误码、时序或预签名响应探测资源？
- 任一凭据、URL 或 Upload ID 是否可能进入日志、审计或异常？
- M2-02 是否能在不修改领域决策的情况下实现 MinIO/OSS 端口？

任何强制项失败则 M2-01 不通过，禁止进入 M2-02。
