# M2-CLOSE-05 产品范围与阶段治理验收标准

> 状态：ACTIVE  
> 原则：产品范围、文档状态、四方签署、main CI 和标签顺序均为硬门禁。

## A. 产品范围

1. 资产列表展示名称、大小、状态、完整性和必要的操作入口。
2. 用户可查看资产详情并对 AVAILABLE 资产发起授权下载。
3. QUARANTINED、DELETING、DELETED 等状态不提供错误的下载能力。
4. 真实浏览器、真实认证、真实 PostgreSQL 与真实对象存储链路通过。
5. 任何未实现的计划能力必须补齐，或取得产品负责人的明确范围变更签署。

## B. 文档治理

1. `docs/CURRENT_STATUS.md` 只保留一个无矛盾的当前结论，历史过程明确标注为历史。
2. `docs/acceptance/README.md` 完整索引 M2-00～08 和 CLOSE-01～05，状态与验收记录一致。
3. M2 实施计划的当前下一步与实际阶段一致。
4. `M1交接文档TO_M2.md` 标记为历史快照并链接当前状态。
5. M2-08 文档明确区分代码/CI、MinIO E2E、OSS E2E 和最终阶段验收。

## C. 总体验收与发布

1. 形成 M2 总体验收报告，逐项引用可复核的提交、CI run 和真实环境证据。
2. 产品、技术、安全、QA 四方分别给出通过结论；不得以“专家评审已组织”替代签署。
3. 工作分支无未提交变更，分支 CI 成功。
4. 合并 main 后，main CI 必须成功。
5. 仅在上述步骤全部完成后创建不可变 `m2-accepted` 标签，且标签必须指向已验证的 main 提交。

## D. 失败条件

任一产品缺口无范围变更、任一权威文档矛盾、任一签署缺失、main CI 未成功或提前创建标签，均判定 M2-CLOSE-05 不通过。
