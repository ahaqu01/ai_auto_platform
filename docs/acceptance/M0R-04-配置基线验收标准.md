# M0R-04 配置基线验收标准

> Status: READY
> Work package: M0R-04
> Baseline: `fa8baef`
> Scope: API runtime settings, environment template and development Compose

## 1. 目标

建立可审计、可测试的配置基线：本地开发保留明确的本机默认值；Staging 和 Production 必须显式提供外部依赖配置，且不得误用 loopback、本地开发地址或不安全的公开端点；环境变量模板必须与运行时代码一致；Compose 配置不得产生 obsolete 告警。

## 2. 验收标准

| ID | 验收标准 | 证据 |
|---|---|---|
| CFG-01 | `local` 环境可使用明确的本机开发默认值 | Settings 单元测试 |
| CFG-02 | `staging` 和 `production` 缺少必需外部依赖配置时启动失败 | Settings 单元测试 |
| CFG-03 | 非本地环境拒绝 localhost、loopback 和本地默认数据库凭证 | Settings 单元测试 |
| CFG-04 | Staging/Production 的 OIDC issuer 与 OSS public endpoint 必须使用 HTTPS | Settings 单元测试 |
| CFG-05 | 错误信息只列配置项名称，不回显 URL、密码、Token 或密钥值 | 异常消息断言 |
| CFG-06 | `.env.example` 包含运行时支持的配置名，无 `KEYCLOAK_CLIENT_ID`/`OIDC_AUDIENCE` 错配 | 模板契约测试 |
| CFG-07 | `.env.example` 只含可公开的本地示例，不含真实凭证 | 敏感模式扫描 |
| CFG-08 | Compose 删除 obsolete `version`，`docker compose config` 无 obsolete 告警 | Compose 契约测试 |
| CFG-09 | 开发服务端口仅绑定 loopback，开发凭证明确标记为 local-only | Compose 契约测试与文档 |
| CFG-10 | 配置专项测试及 API/Web/Agent/迁移全量回归通过 | 验证记录 |

## 3. 测试优先要求

实现前先执行新增配置测试。预期至少因以下现状失败：Staging 不校验、本地地址可进入 Production、环境变量名称错配、Compose 含 obsolete `version`。失败必须来自配置基线缺失，而不是 Docker、导入或测试环境损坏。

## 4. 范围边界

- 本工作包不引入真实 Keycloak、Temporal 或 OSS 凭证。
- 不改变数据库结构和业务 API。
- 不把开发默认凭证推广到 Staging/Production。
- Secret Manager、KMS 和凭证轮换在部署/IaC 工作包落地，本阶段只建立配置接口和失败保护。

## 5. 完成定义

CFG-01 至 CFG-10 通过后可标记为 `IMPLEMENTED_LOCAL`。没有独立评审、CI 和 Staging 启动证据时，不得标记为 `REVIEWED`、`VERIFIED_STAGING` 或 `ACCEPTED`。
